# Luma Implementation Plan

更新日期：2026-11-09。**只定义执行顺序、任务边界、依赖和完成条件，不维护第二份完成状态。** 当前实现见 [progress](progress.md)，实际检查见 [verification](verification.md)，业务范围见 [PRD](../spec/PRD.md)。B为业务任务，AG为Agent机制，T为伴学体验；M01～M09仅为模块标签，不再另列重复施工清单。

## 1 执行顺序

**本次顺序调整：优先B05最小文字练习闭环。** 接通真实练习卡→说明→开始/继续→逐题文字作答与自动保存→携题追问/返回→提交→逐题自评→反馈；以已有题组点验，不新增付费生成。普通开始复用最近轮次，完成轮只读。照片依赖B03，显式重做及历史切换保留为B05后续子项；不能将本批标为整个B05完成。完成后接回下列剩余有限验收与AG02.4，不另建一套任务清单。

1. **T01收口真实教学样例**：用微信工具验证配图协议、坐标轴变量、图文对应、默认答案边界和失败反馈；图注复用正文公式渲染，不重新调用模型。检查共享修正额度与局部补丁，保留服务端诊断。单图通过不能冒充多图验收。真实验证不在学生输入额外添加“不要答案”；不另跑后台模型批测，不自动重复付费请求。不重复实现加载器，不做生产构建或部署。
2. **B02/B04/B04-R剩余有限验收：图文触发、成果卡与阅读焦点**：基于现有主动讲义、按轮材料卡和阅读焦点接线，补直接请求/复用、历史练习失败隔离、停止与滚动跟随的有限点验。保留学生限制、预算、解析权限及去重；图文自主触发不扩成自动练习/总结卡。生成中只显示动画与材料类型，成功原位更新对应入口，失败重试绑定原任务。练习进入真实文字闭环，不与旧讲义混用。核对不代学生新增意图；末节追问定位准确。优先读取已有材料，不自动追加付费生成；工程与真实教学证据分别记录，保持正文流式与既有轻量风格，不在此扩展照片、重做和历史切换。
3. **随后AG02.4调用前预算预留，AG04随路径修补**：沿用AG02.3的近期轮次、覆盖审计与结果回读，补累计剩余额度/unknown/恢复对账；不新建记忆平台。本轮只作离线与隔离真库验证，真实GPT语义抽验另留验收，不自动付费批测。
4. **T02 → T03**：路线/验证持久化与对话内轻量进展，每项落成可操作小闭环。
5. **B03 → B05 → B06 → B04-S**：上传视觉、正式练习、学习记录及主动总结图卡；B06必要返回/恢复随前序接线，不等最后一次性接入。
6. **T04/AG05完整场景收口 → B07体验版交付**：真实微信、真机和线上部署放交付阶段。

每项以完成条件为边界，不把内部机制全部写完才联调；未完成列表只在progress维护。不得因新增T任务删除原有图文、练习、错题或总结卡；三周目标不因文档重排重新起算。

## 3 Agent机制

机制只在 [agent](../design/agent.md) 定义，数据只在 [data-api](../design/data-api.md) 定义。本表保留可实施粒度，不复制伪代码或测试流水。

| ID | 实施范围与完成条件 |
| --- | --- |
| AG01 | 公共身份/运行时通用，数学规则集中；提示、概念、纠错不机械共用禁答规则，不引入多学科路由 |
| AG02.1 | TeachingMemory稳定ID、来源、状态/版本、解决/替代/冲突和旧数据保留；同轮要求进入材料EvidencePack，不把错误尝试当事实 |
| AG02.2 | 受控字面搜索→原文精确/所属轮次读取→预算续读；先隔离权限，搜索片段不算已读，无依据澄清 |
| AG02.3 | 依赖.1/.2；保护最近3完整轮次和开放尾部，旧只读结果卸载为可回读引用，必要时80%滚动摘要；覆盖清单按版本独立审计、失效引用过滤与旧游标重建；不重放写操作、不复活旧条件；来源/覆盖校验与语义验收分别取证 |
| AG02.4 | 调用前预留输入/输出，unknown保守占用，预算跨恢复累计；稳定缓存前缀；AC-23完整矩阵有工程与真实语义证据，不仅计测试数 |
| AG03 | 扩充实际所需关系/过程图；沿用函数/几何能力及局部快照，不把所有内容塞入抛物线或固定三段；题组校验/有限质量修复 |
| AG04 | 成功无进展、截断、分类有限重试、SSE心跳/静默后数据库对账；参数未完整不执行、材料未完整不发布、断流不重复成果 |
| AG05 | 约12类运行/教学行为场景，结合约20道高中数学代表题；保存来源、轨迹、耗时/用量及限制，数学正确性抽查；与T04复用样例 |

AG03随材料和练习接入，AG04/AG05贯穿，不建立独立平台阶段。教材RAG、向量库、长期画像、多Agent、自建KV cache及精细结算暂缓；现有来源记忆和按需回读不因此省略。

## 5 执行与同步约定

- 在feature开发，每项先说明实施范围，再做最小闭环；当前使用微信开发者工具+本地API/数据库/worker，不以真机、部署或生产构建为开发前置。
- **每次有实际进展，同一轮更新progress原条目；计划发生变化时更新本文件，有检查就将输入/结果/限制写入verification。** 未跑检查明确“未验证”，不能只在对话口头报告或追加矛盾日志。
- 需求/验收变化同步spec；交互或机制变化只改对应design。仅实现状态变化不得改写需求或重复新建评审。
- 每批说明变更及验证，用户确认后才commit、push；按任务点提交，已授权上一批不等于授权下一批。
- 总投入三周约69～84小时为竞赛目标预算，剩余排期依据实际任务进展调整；P1导出、裁剪、新卷复测、视频不进入当前开发。
