# Luma 技术决策

依据：[PRD](../spec/PRD.md)。整理日期：2026-11-05。

**职责：记录用什么技术、为何采用及适用边界。** 执行流程只维护在 [Agent 设计](agent.md)，数据协议只维护在 [数据接口设计](data-api.md)，不在此重复任务清单与验收结果。

## 1 技术栈

采用 TypeScript 全栈。前端使用 uni-app、Vue 3 编译为微信小程序，服务端使用 Next.js。教学 Agent 通过工具调用组织 GPT 的识别、引导、图文生成和练习生成能力，个人学习记录保存在服务端。首期交付体验版，添加老师为体验成员后扫码使用。

| 模块 | 选型 | 用途 |
| --- | --- | --- |
| 小程序前端 | uni-app、Vue 3、TypeScript，编译目标 mp-weixin | 学习页面、微信登录、拍照上传与原生交互 |
| 服务端 | Next.js Route Handlers、TypeScript、Node.js | 鉴权、上传、数据接口与 Agent 服务 |
| Agent 调用层 | Vercel AI SDK | GPT 流式输出、工具调用和多步骤执行 |
| 主模型 | GPT | 图片理解、启发式答疑、讲义与练习生成、内容复核 |
| 教学配图 | GPT 图片生成能力 | 按当前讲解生成和修改教学配图 |
| 数据约束 | Zod | 校验模型输出的结构和必填字段 |
| 内容呈现 | Markdown 解析、小程序富文本、公式图片 | 正文和 GPT 配图使用原生组件；LaTeX 在服务端用 KaTeX 渲染并转成图片缓存 |
| 数据库 | PostgreSQL、Prisma | 个人学习数据保存、查询与迁移 |
| 文件存储 | 腾讯云 COS | 原图、作答照片、生成配图及 PDF |
| 草稿缓存 | uni-app Storage | 按账号和练习保存有容量限制的草稿，图片同步到对象存储 |
| 部署 | Docker | 部署 Next.js 服务及任务执行进程 |
| 开发与验证 | VS Code / Codex、微信开发者工具、真机、教学样例集 | 小程序编译、调试、扫码预览、体验版上传及教学核验 |

前端、服务端与工具使用 TypeScript，前端组件使用 Vue 3。GPT 由服务端统一配置，密钥保留在服务端。多模态理解和图片生成按各自接口能力接入。个人类型小程序不支持 web-view，首期直接编译为小程序页面，不嵌入 H5。

## 2 决策与取舍

| 决策 | 原因与边界 |
| --- | --- |
| 原生小程序编译目标 | 适配个人主体及体验版交付；使用 uni-app 编译微信页面，原型 HTML 仅作参考 |
| TypeScript 全栈 | 复用当前工程与前后端共享 schema，不引入 Python 服务 |
| 现有 AI SDK + 自有单层循环 | SDK 适配模型协议；项目负责工具执行、预算、等待与持久化，不叠加第二套编排框架 |
| GPT 统一服务端配置 | 理解、教学、出题、复核及图片生成均走服务端；按各自 API 能力适配，学生无需配置模型 |
| 模型生成教学配图 | 教学内容与配图由模型承担；KaTeX/图片转换仅展示公式，不替代模型教学生成 |
| PostgreSQL + 单 worker | 竞赛版复用数据库任务状态、幂等和等待恢复，暂不引入 Redis 或通用工作流平台 |
| COS 私有文件 | 保存原图、作答照片与生成配图，文件归属与访问权限由服务端校验 |
| 数据库关联读取记忆 | 当前题、讲义段落和练习都有明确引用，首期不需要教材 RAG、向量召回或重排 |
| 关键事实 + 有限近期消息 | 保留确认题干与当前目标；超预算请求缩小范围，自动摘要后续再做 |
| 基础恢复与日志 | 完成防循环、有限重试、状态恢复及消耗记录，不做分布式调度或精细费用结算 |

## 3 后续引入条件

| 能力 | 引入时机 |
| --- | --- |
| 教材 RAG / pgvector | 需要按指定教材章节检索并提供可靠引用，且已明确资料来源与使用范围 |
| 自动摘要压缩 | 当前上下文预算在真实多轮样例中持续不足，再增加保真评测 |
| PDF 导出、精细裁剪、新题复测 | P0 闭环稳定后的 P1 迭代 |
| 多 Agent、长期学习画像、分布式运行平台 | 首期不纳入；出现经验证的需求后另行评估 |

GPT 托管推理的 KV cache 无需本项目自行实现；提示词缓存是后续成本优化项，不是首期交付前置条件。
