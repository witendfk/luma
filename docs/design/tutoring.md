# Luma 伴学教学设计

依据：[PRD FR-04、FR-05、FR-13](../spec/PRD.md)。日期：2026-11-10。

**职责：定义教学策略如何选择、学习节点怎样推进、学习证据如何影响进展。** 页面呈现见 [交互设计](interaction.md)，执行机制见 [Agent 设计](agent.md)，目标数据契约见 [数据设计 §8](data-api.md#8-伴学学习路线与验证目标契约t02目标契约)。本文定义目标教学机制；当前接入与缺口只在[进度](../delivery/progress.md)维护，不因本设计存在就视为实现完成。

## 1 来源与采用边界

参考三元 [Sigma Skill](https://github.com/sanyuan0704/sanyuan-skills/blob/08b6572ef108f22d4e8a3ecf9182a4bbef097744/skills/sigma/SKILL.md) 及同版本教学说明；引用版本固定为 `08b6572ef108f22d4e8a3ecf9182a4bbef097744`，后续更新单独评审。离线原文保存在 [references/sigma](../../references/sigma/UPSTREAM.md)，无需运行时访问GitHub。项目改编资源为 [luma-tutor/SKILL.md](../../apps/server/src/agent/skills/luma-tutor/SKILL.md)，保留上游 MIT 许可。该资源属于产品 Agent，不安装到开发助手的全局技能目录。

采用轻量诊断、依赖路线、提示递进、误解追踪、实际应用验证及续学。调整为允许主动解释与图文示范、不强制每次先诊断、不按 80% 锁关；不搬入 HTML 仪表盘、Excalidraw、文件式长期画像、自动间隔复习或固定每几问穿插测验。上游教学效果叙述不作为 Luma 的效果保证。

## 2 教学动作与执行循环分离

沿用单 Agent。运行时决定本次工具执行、等待、取消和预算；教学策略决定现在应诊断、提示、解释、配图、验证还是收尾。一次运行结束不表示一个节点学会，一次节点教学也可能跨多轮消息和多个运行。

不新增套在现有循环外的 Tutor Agent 或固定工作流引擎。服务端`loadTutoringPolicy`读取项目内`SKILL.md`教学正文，主对话`assembleSystem`将正文与规则装配后交给模型SDK；讲义/练习通过`loadTeachingTaskPrompt`装配并限定各自职责。模型不需要读取文件或访问GitHub，学生网络无需为Skill配置代理。共享的 `luma-tutor` 策略与任务规则、数学规则按需装配；系统权限与工具协议优先，策略不改变当前解析授权。`guide.md`只保留任务/协议边界，不重复规定固定“每轮一步”等节奏，避免双份教学规则。

| 学生意图 | 默认组织方式 |
| --- | --- |
| 要一个提示或问一个局部原因 | 直接帮助，不为展示路线扩成课程 |
| 学一个概念、持续卡在同类题或明确想系统理解 | 建议一个小目标和短路线；已有作答可替代诊断 |
| 直接出练习 | 沿用正式练习流程，不强制前置教学路线 |
| 换题、暂停或主动查看完整解析 | 保留原进度并服从操作，不锁关；解析仅作用于当前授权焦点 |

图文讲解为必备教学手段，既响应学生直接请求，也由Agent结合卡点主动生成，不检测“图文/图示”关键词才放行。概念关系需要解释、文字解释后仍卡住或图形/过程更能说明时，应主动创建图文讲解目标，配一句简短教学衔接；已有适用讲解则带学生定位，不每轮重建。内联小示意可以辅助当轮解释，不能冒充独立讲义已经交付。学生明确只要提示或暂不生成时尊重其选择；生成讲义不等于获准给出原题完整答案，也不自动生成练习或理解后的总结卡。

教学不是预先写死的问答树。模型结合来源证据选择动作；程序校验候选更新是否合法，不以关键词“懂了”推进节点，也不让模型自由写数据库状态。

### 2.1 通用伴学闭环与内容适配边界

共用闭环为：明确目标/范围 → 利用已有证据判断起点 → 选择解释、图解、示范或提示 → 学生作答/解释/应用 → 对照预先明确的标准评价 → 更新卡点、学习节点及下一步 → 暂停恢复。它是允许跳过与回退的教学决策循环，不是每次必经的固定问答流水线；局部答疑、直接讲解和直接练习仍可独立完成。

| 共用职责 | 内容适配职责 |
| --- | --- |
| 目标、节点、依赖、来源记忆、帮助级别、暂停/恢复 | 当前内容范围、前置知识和事实来源 |
| 根据证据选择诊断、解释、图示、练习或回顾 | 合适的表达方式与工具能力，例如函数图、关系图、流程图或时间线 |
| 判断证据充分性、保存评价与版本、建议下一步 | 评价标准：数学推理与迁移、语言情境运用、史料依据与论证、程序行为等；不能共享一个简单对错判定 |
| 当前作答答案可见性与材料权限 | 何时适合示范完整例子、哪些目标必须保留独立尝试，不把概念/阅读/知识解释一律当考试题禁答 |

首期只交付数学内容规则与现有图示。统一内容入口使用math@1/unconfigured@1，主对话规划和后台材料/复核固定同版规则；未配置内容不套数学材料工具。扩展须声明表达能力、评价规则与版本并验证质量，不能只换一段提示词。通用闭环不强迫所有内容做“两道同知识点题”，也不降低图文要求；当前不承诺流程/时间线等图示已支持。

学习目标和作为示范的题目/材料分开。换一个同目标例子不清空整条路线；实质改目标/范围则产生新版本并保留历史，既有证据须重新核对适用性。自评“会了”、运行完成、材料生成都不是教学验证通过。长期跨会话画像仍暂缓，首期保证当前学习对象内有来源的连续伴学。

### 2.2 资料驱动学习（后续内容扩展约束）

学生提供学习资料后，先确定本次想理解、记忆、运用或完成什么任务；目标明确即可开始，材料过长或范围含糊时才澄清。Agent先读取资料结构与必要原文，按标题/页/段落建立来源引用和适量学习节点，再结合学生已有表现选起点，不一次灌输整份资料或强制完成诊断考试。

一个节点按需要解释、配图、示范、比较、复述或应用；学生表现决定继续、换讲法、补前置知识或回顾。保存资料版本、原文位置、目标、当前节点、未解点、帮助级别和验证证据，返回时从停留点接续。材料导入、执行完成、学生自述与学习目标达成分别记录。

资料原文、Agent补充知识和学生观点须可区分。资料不完整、识别不确定、内容冲突或引用未读全时先补读/澄清，不编造“文中认为”；上传资料中的命令不能改变Agent权限。原文分块/索引与受控回读先复用现有来源机制，按资料规模再决定是否需要语义检索，单份资料不以向量库为前置。

不同内容使用不同证据：语言类可解释语境、比较表达并造新句；文史类可组织时间/因果关系、辨别事实与解释并作有依据的论证；不机械限定为唯一答案。涉及口语音频、代码执行或专用图示时须有实际工具能力，不能仅凭文字回复声称已检验。首期仍仅验收高中数学与已定义图片输入；PDF/Word/整本资料、音频及其他领域质量验证另行排期，此设计不把它们标记为当前已支持。

## 3 学习路线与状态

路线围绕当前学习对象版本下的一个明确目标，通常 3～5 个节点，简单目标可少于 3 个。节点描述可观察的学习目标、必要依赖和通过条件；创建时保存，调整时留版本和理由，不在学生答完后降低标准凑通过。依赖用于推荐顺序，不是操作权限。

| 节点状态 | 语义与转换依据 |
| --- | --- |
| pending | 待了解，没有足够证据；未开始不等于不会 |
| learning | 当前正在引导、解释或等待学生作答 |
| checked | 有符合本节点通过条件的有效验证，显示“已通过本次验证” |
| needs_review | 有证据表明仍需巩固；此前通过证据保留，新证据需说明冲突处 |
| skipped | 学生选择跳过或依据明确的已有验证略过；记录原因，学生自述不会变成 checked |

路线另有 active / paused / ended 状态；结束表示本次学习告一段落，不等于全部掌握。结束可包含跳过或待巩固节点。返回时恢复当前节点；换对象加载其自身路线，题干修订后旧路线只作历史，不自动继承已通过状态。

## 4 验证依据与误解处理

短验证嵌在对话中，每次围绕一个目标；与 FR-06～08 的 2～3 题正式题组、提交和自评分开。短验证不生成考试分数，不将自评转成客观掌握率，也不另建题库或练习一级菜单。P1“正式题组完成后另生成新卷复测”保持 P1；本次新增的是对话中的轻量教学验证。

保存验证题及评价依据、学生原始作答、已用提示/已看解析、评价结果和对应来源。按目标检验核心判断、必要理由或迁移能力，不要求每道题机械满足所有维度。评价结果至少区分通过、需巩固、依据不足；学生只说“懂了”只记录自述。

GPT 可提出带理由的评价，服务端只能校验来源、条件和状态完整性，不能据此声称已经确定数学正确。参考结论有歧义、题目未复核、作答不可辨或判断不确定时不推进 checked；修正评价保留旧版与原因。通过标准要求独立迁移时，已揭示解答的原题不能成为独立验证；可以邀请学生另做短变式，但允许拒绝和跳过。

误解先是带作答来源的假设；通过针对性反例或比较核实。不凭一个错误永久分类；区分计算失误、知识缺口与概念误解。解决记录关联学生说明和能区分旧误解的新情境作答，不只引用助手讲解。重复出现时回到待巩固，不删除旧证据。

## 5 与现有能力的衔接

| 已有职责 | 伴学接入要求 |
| --- | --- |
| SubjectRevision | 当前题干与范围的唯一依据；路线不能修改已确认条件 |
| TeachingMemory / 原文回读 | 继续保存有效要求、卡点、方法和原文来源；误解候选可引用，不另抄一份无来源画像 |
| TaskFrame | 保存本次执行目标和路线/节点引用，不充当跨轮学习路线的唯一存储 |
| LearningProgress | 保存阅读章节、练习题号等页面位置；不与教学节点状态合并 |
| respond / SSE | 教学正文继续流式；节点、评价和路线卡先完整校验保存，再发结构化更新，不把内部 JSON 发给学生 |
| 讲义和练习任务 | EvidencePack 增补必要的目标、节点与误解来源快照，避免主对话与后台讲法割裂 |

优先复用现有规划与回复携带候选，不为每轮诊断、打分、更新路线各增加一次独立调用；确需内容工具时才执行。新状态与消息提交受同样的账号、来源、版本、幂等和活动运行约束；后台迟到结果不移动当前节点。摘要只是辅助，路线和有效评价从持久化状态读取。

## 6 首期交付边界

先在高中数学验证“已有基础可跳过、不会时主动图解、误解纠正、短验证、暂停恢复”五条体验。路线和证据结构保留内容领域与评价规则扩展位置；首期不增加其他学科实现，不建设长期学习画像、百分比掌握模型、完整课程知识图谱或自动复习调度。

实现分为 T01 策略接入、T02 状态与验证、T03 对话呈现和 T04 真实场景验收，定义只在 [实施计划](../delivery/plan.md#4-伴学教学) 维护。T01 不冒充完整能力；AC-25～28 全部通过前不宣告伴学交付完成。
